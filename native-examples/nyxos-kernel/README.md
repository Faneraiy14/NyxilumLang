# Реальні модулі ядра NyxOS, переписані мовою NyxilumLang

Фаза N7 (`NATIVE_ROADMAP.md`, корінь репозиторію) - доказ, що
`nx compile-native --target nyxos-kernel` може породжувати C-ABI-
сумісний `.o`, придатний влитись у РЕАЛЬНУ збірку ядра NyxOS
(`cyklokoalicia`... тобто [NyxOS](https://github.com/Faneraiy14/NyxOS),
`build.sh`).

## Файли

- **`kstring.nx`** - повний, точний переклад `src/kstring.c` з
  репозиторію NyxOS (`k_strlen`, `k_streq`, `k_starts_with`,
  `k_strcpy`). Підмінено замість оригінального `kstring.o` в
  РЕАЛЬНІЙ збірці ядра й перевірено живцем у QEMU - завантажується
  ІДЕНТИЧНО оригіналу.
- **`gconsole.nx`** - повний переклад `src/gconsole.c` (пікселева
  консоль - `gconsole_init`/`gconsole_putc`/`gconsole_print`/
  `gconsole_refresh`/прокрутка). Глобальний стан (`grid`/`col`/`row`/
  кольори) - через справжні глобальні змінні (`var` на верхньому
  рівні файлу, Фаза N7). Сітка символів - `kmalloc()`-виділений
  буфер (замість C-масиву фіксованого розміру, якого NyxilumLang
  синтаксично не має) з ручною row-major індексацією. UTF-8-
  декодування кирилиці - ЧИСТОЮ арифметикою (`%`, `*`, порівняння
  діапазонів) замість бітових операцій (`&`, `<<`), яких мова НЕ має
  взагалі - математично точно еквівалентно оригінальному
  побітовому алгоритму (перевірено: codepoint для "Ап" дає рівно
  1040/1087, як і UTF-8 справді кодує U+0410/U+043F).
- **`kernel_calls_demo.nx`** - невеликий демонстраційний файл (НЕ з
  реального NyxOS) для перевірки виклику однієї kernel-функції з
  іншої й `kmalloc`/`kfree`.

## Як перевірити самостійно

```bash
nx compile-native kstring.nx -o kstring --target nyxos-kernel
# -> kstring.o - звичайний релокований ELF-об'єкт, .global k_strlen/
#    k_streq/k_starts_with/k_strcpy, БЕЗ main/_start/syscall'ів.
```

Живий доказ (переказ із сесії 15.09.2026):

1. Скомпільовано в `.o`, підключено до окремого **freestanding**
   C-тесту (`gcc -m32 -ffreestanding -nostdlib`, БЕЗ libc, БЕЗ
   жодного зв'язку з NyxOS) - усі перевірки (значення/крайові
   випадки) пройшли.
2. **Справжня інтеграція**: `kstring.o`/`gconsole.o` (обидва
   скомпільовані ЦИМ компілятором) підмінено замість оригінальних
   у РЕАЛЬНІЙ команді `ld` з `build.sh` репозиторію NyxOS,
   перелінковано, завантажено в QEMU headless - ядро завантажується
   без жодного краху, аж до готовності shell (той самий серійний
   лог, що й з оригінальним C-кодом).
3. Під час цього знайдено й виправлено реальний баг НА БОЦІ NyxOS:
   ядро ніколи не вмикало SSE2 (CR0/CR4) - без цього БУДЬ-ЯКА
   SSE2-інструкція (весь код цього компілятора використовує SSE2
   для чисел) падає з Invalid Opcode. Виправлено в
   `src/kernel.c::enable_sse()` репозиторію NyxOS.

**Відома, чесно задокументована прогалина**: живий тест у QEMU (крок
2) НЕ мав реального VBE/framebuffer (`[GFX] GRUB ne dav framebuffer`
у серійному лозі цієї конкретної конфігурації QEMU) - тому
`gfx_is_available()` повертав `false`, і gconsole-логіка (запис у
сітку, виклики `gfx_draw_char` тощо) реально НЕ виконувалась під час
цього ЖИВОГО тесту в справжньому ядрі - лише пройшла перевірку
лінкування й "не зламала завантаження". Повна поведінкова перевірка
(правильні координати/символи/UTF-8-декодування) зроблена ОКРЕМО,
через freestanding C-тест із заглушками `gfx_*` (крок 1) - не в
самому ядрі. Живий тест gconsole З РЕАЛЬНИМ framebuffer - окремий
майбутній крок (потребує іншої конфігурації QEMU чи реального
заліза).
