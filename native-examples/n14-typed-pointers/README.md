# Фаза N14 - справжні типізовані вказівники `ptr<T>` (живий тест)

Той самий підхід, що n12/n13 - freestanding `gcc -m32 -ffreestanding
-nostdlib` C-гарнес.

## Нове в мові

`ptr<T>` - НОВА форма анотації типу (`T` - `number`/`int8`/`uint8`/
`int16`/`uint16`/`int32`/`uint32`), розпізнається `Parser.cs`
(`ParseType()`) як спеціальний, ЄДИНИЙ дозволений випадок "ім'я<...>"
- НЕ повноцінні дженерики для всієї мови. Використовується як тип
параметра/return-типу/глобальної змінної, той самий синтаксис, що
`string`/`int32`/тощо:

```
func readI32(p: ptr<int32>, i: i32) -> int32 {
    return p[i]      // масштабоване читання - i-й int32, НЕ i-й байт
}

func advance(p: ptr<int32>) -> ptr<int32> {
    return p + 1      // адреса + 1*sizeof(int32), НЕ +1 байт
}
```

## Файли

- **`n14_test.nx`** - 9 kernel-функцій/перевірок: базове читання/
  запис `ptr<int32>`/`ptr<uint8>`/`ptr<int16>`, арифметика вказівників
  з РІЗНИМ масштабом (4 байти для int32, 1 байт для uint8 - разом
  доводять, що масштаб реально залежить від T), порівняння з null і
  між вказівниками.
- **`harness.c`** - виділяє тестові буфери як звичайні C-масиви
  (.bss), передає їх адреси в NyxilumLang-функції як звичайні
  cdecl-покажчики.

## Як перевірити самостійно

```bash
nx compile-native n14_test.nx -o n14_test --target nyxos-kernel
gcc -m32 -std=gnu11 -ffreestanding -nostdlib -fno-stack-protector -c harness.c -o harness.o
ld -m elf_i386 -e _start harness.o n14_test.o -o n14run
./n14run; echo "fail_mask: $?"   # 0 = усі 9 перевірок пройшли
```

Санітарна самоперевірка (підміна одного очікування на завідомо
неправильне) підтвердила, що тест реально ловить розбіжності.

## Реалізація (коротко)

- `ValType.Ptr` - ОДИН новий тег (не по одному на кожен T) -
  `NativeCodegen.cs`, `_ptrElementType`/`_globalPtrElementType` -
  зберігають тип ЕЛЕМЕНТА "збоку" (bare enum не може нести параметр
  типу), той самий патерн, що `_varStructName` для `ValType.Struct`.
- `ptr[i]`/`ptr + N` - НАПРЯМУ x86-адресація `(%eax,%ecx,SCALE)` для
  індексування (природна підтримка масштабів 1/2/4/8 - точнісінько
  ширини всіх sized-int типів і `double`), явний `imul` для `+`/`-`
  (SCALE-адресація тут не масштабує від'ємно для `-`).
