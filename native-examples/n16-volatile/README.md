# Фаза N16 - явний `volatile` (живий тест)

Останній пункт плану N12-N16. `var volatile x: T;` - НАРАЗІ
семантично no-op (компілятор не робить ЖОДНОЇ оптимізації з
переупорядкуванням/кешуванням пам'яті - кожен вираз компілюється
прямолінійно, факт, уже задокументований раніше цим самим
NATIVE_ROADMAP.md для Фаз N10/N11). Цінність зараз - (а) самодокументація
для читача `.nx`-коду ("це MMIO-регістр, не звичайна змінна"), (б)
страховка на майбутнє, якщо компілятор колись отримає реальні
оптимізації.

## Файли

- **`n16_test.nx`** - глобальна `volatile` і локальна `var volatile`.
- **`n16_test_novol.nx`** - ПОБУКВЕННО той самий файл, БЕЗ жодного
  `volatile` - для побайтового порівняння.
- **`harness.c`** - функціональна перевірка (чи взагалі
  volatile-змінна працює як звичайна - 2 перевірки).

## Як перевірити самостійно

```bash
# Доказ "справді no-op ЗАРАЗ" - не голослівне твердження
nx compile-native n16_test.nx -o n16_test --target nyxos-kernel
nx compile-native n16_test_novol.nx -o n16_test_novol --target nyxos-kernel
diff n16_test.s n16_test_novol.s   # МАЄ бути порожній

# Функціональна перевірка
gcc -m32 -std=gnu11 -ffreestanding -nostdlib -fno-stack-protector -c harness.c -o harness.o
ld -m elf_i386 -e _start harness.o n16_test.o -o n16run
./n16run; echo "fail_mask: $?"   # 0 = обидві перевірки пройшли
```

Живцем підтверджено: `diff` між файлом із `volatile` і без нього дає
ПОРОЖНІЙ вивід - генерований асемблер побайтово ІДЕНТИЧНИЙ.
